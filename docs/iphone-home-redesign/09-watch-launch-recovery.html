Required bootstrap order

Open normal store → on failure log the exact error and quarantine only default.store, -shm, and -wal → retry a new persistent store → if that also fails, render this recovery surface over an in-memory container. There is no fatalError launch path.

Data wording

Do not claim all Watch data is safe: an unsynced Watch workout may exist in the quarantined store. State only that iPhone data is unaffected. Keep the quarantined files for diagnostics/recovery until a separately specified retention policy exists.

Proof before fix

Collect the device crash report and launch logs. The current leading cause is the model-container fatalError, likely exposed by an incompatible Watch-local schema after upgrade. If the crash stack differs, preserve the same nonfatal UX but fix the proven launch stage.

Completion evidence

Unit-test fail-first and fail-twice bootstrap paths. Watch smoke-test cold launch, five relaunches, and an upgrade from the prior build with existing data. The root or recovery identifier must remain visible for at least 10 seconds.
